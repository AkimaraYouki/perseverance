# 로봇 → 데스크톱: 유선(책상 디버그) 연결 — 학교 LAN 에 ARP 스푸핑, 데스크톱 쪽 설정 필요

사용자: 데스크톱 유선 **192.168.55.112**. 유선은 **책상 디버그 전용**, 대회·실외는 Wi-Fi 만 (전용 TP-Link AP 곧 도착).

## 측정
- Jetson 192.168.54.23 → 데스크톱 192.168.55.112 (학교 라우터 192.168.54.1 경유): **손실 60 %**. 직접(on-link): **40 %**.
- 원인 [arping 확인]: **`2C:F0:5D:8F:E4:12`(MSI) 가 남의 IP 에 ARP 응답**한다 — 게이트웨이 192.168.54.1
  (진짜 `00:FE:C8:25:1E:3F`)와 **데스크톱 192.168.55.112 (진짜 `BC:FC:E7:63:8B:BD`)** 둘 다. 학교망 ARP 스푸핑이다.
- Jetson 쪽에 데스크톱을 **on-link /32 경로 + 고정 ARP** 로 박았더니: 30/30, **손실 0 %, 중앙 0.68 ms**.
  NM 훅(`91-gen2-wired-peers`)이 유선 연결 때마다 자동으로 건다. DDS 피어에 192.168.55.112 추가, SPDP 가 나가는 것 확인.

## 데스크톱에서 할 것 (반대 방향도 스푸핑에 노출돼 있다)
```bash
IF=<데스크톱 유선 인터페이스 이름>
sudo ip route replace 192.168.54.23/32 dev $IF                                    # 라우터 거치지 말고 직접
sudo ip neigh replace 192.168.54.23 lladdr 3c:6d:66:b5:0f:09 dev $IF nud permanent  # Jetson 진짜 MAC 고정
ping -c 30 -i 0.2 192.168.54.23                                                   # 손실 0 % 확인
```
- FastDDS 프로필: 지금 Wi-Fi 인터페이스로만 제한돼 있을 것 — 유선 디버그 때는 **유선 인터페이스 + 초기 피어 192.168.54.23** 을 쓰는
  프로필을 따로 두면 된다. Jetson 쪽은 유선에서 멀티캐스트를 껐으니 피어가 반드시 있어야 발견된다.
- 이 스푸핑 장치는 학교망 관리자에게 알릴 만하다 (사용자에게도 전했다).
