## 1. 첫 제어기 — VMC + LQR (사용자 결정)

사용자가 Liu & Wang (2024, Emerging Science Innovation 4:17-32) 구조로 먼저 제어하기로 했다.
`sim/control/vmc_lqr_design.py` 가 이 로봇 파라미터로 게인을 푼다 → `sim/control/gains.yaml`.

```
직진  T_theta = -K(h) · [θ, θ̇, x - x_d, ẋ - v_d]      (두 바퀴 합, Nm)
      K_j(h) = p0 + p1 h + p2 h²   (h = 지면~고관절 [m], gains.yaml 의 poly_p0_p1_p2)
조향  T_delta = PID(δ_d - δ)
분배  T_L = 0.5 T_theta + 0.5 T_delta,  T_R = 0.5 T_theta - 0.5 T_delta
높이  F_leg = M g / (2 cos θ) + PID(h_d - h)        M = 4.147 kg (바퀴 위 전체, 추정)
      τ_hip = F_leg · leg_map.dh_dtheta(θ_motor)     ← 논문의 J = dL0/dθ1 이 이것이다
```

설계 결과 (Q = diag(6000,1,1000,100), R = 100 — 논문 식 51 그대로):

|---|---|---|---|---|---|---|
| 182.5 | -11.88 | -1.148 | -3.162 | -3.413 | 0.52 Nm | 2.30 Nm |
| 242.5 | -12.79 | -1.437 | -3.162 | -3.331 | 0.56 Nm | 2.37 Nm |
| 302.5 | -13.61 | -1.742 | -3.162 | -3.311 | 0.59 Nm | 2.42 Nm |

전 구간 연속·200 Hz 이산 폐루프 안정. 다항식 적합오차 0.09 %.

## 2. 실기 적용 시 주의

- **모터 피드백 50 Hz → 최소 200 Hz.** 게인은 200 Hz 이산화에서 확인했다. 로봇 쪽 README 도 500~1000 Hz 필요라고 적어 뒀다.
- **바퀴 토크 ↔ 전류.** 마찰 한계 추정 0.82 Nm/바퀴(μ≈0.7, 추정)는 Kt 1.27(미검증) 기준 **약 0.65 A**. 현재 `current_limit_a: 2.0` 은 약 2.5 Nm. 첫 기동은 0.5 Nm 근처로 클램프 권장.
- **고관절 정적 토크 2.3~2.4 Nm = AK60-6 정격 3 Nm 의 80 %.** 서 있기만 해도 연속 부하가 크다. 총질량 5 kg 넘기면 정격 초과(이전 계산 한계 5.14 kg). 온도 감시 필수.
- **θ 부호.** 앞으로 기울면 θ > 0, 양의 바퀴 토크 = 전진. K_θ 가 음수라 T = -K·s 에서 앞으로 기울면 앞으로 민다. iAHRS 장착 방향이 정해지면 이 정의에 맞춰 축/부호부터 맞출 것. 부호가 틀리면 시뮬에서 0.6 s 안에 넘어졌다.
- **센서허브 USB.** C++ 드라이버는 전용 스레드로 계속 읽어서 200 ms 조건은 만족한다. 다만 데스크톱에서 1 s 이상 read 를 멈췄더니 ESP32-C3 가 **USB 에서 떨어지고 재열거되지 않았다** (물리 재삽입 필요). 이 경우 드라이버 재연결로는 복구 안 된다.

## 3. 정정 — 데스크톱이 틀렸던 것

- GPS 무응답 원인을 "보율 아님, 배선/전원" 이라고 했는데 **틀렸다.** 로봇 쪽이 찾은 대로 보율(230400)이었다.
- 앞서 보낸 PD 게인(kp=2.0, kd=0.2)은 액션 스케일 착오로 **실제 적용값의 4/3 배**로 적혀 있었다. 실제 적용된 값은 kp 1.5 Nm, kd 0.15 Nm·s (바퀴당, θ 는 rad). 스크립트 수정함.

## 4. 사용자 확정 사항 (2026-09-24)

- **모터는 4 개**: 다리 AK60-6 V3.0 ×2 + 바퀴 AK45-10 ×2. 로봇 쪽 README 의 "3 motors", `ak60_leg`(단수) 표기를 4 개로 고쳐 달라.
- **실측 총질량 ≈ 모델 + 0.25 kg = 약 4.28 kg** (사용자 추정). 게인은 이 값으로 계산했다. 저울로 재면 알려 달라.
- URDF 는 아직 확정 아님. 확정되면 데스크톱이 게인을 다시 뽑는다.

## 5. 시뮬 쪽 현재 상태 (참고)

- 모델 결함 2 건 수정: 전진축이 Y 였던 것 → +X, 바퀴 회전자 관성 이중계상 제거. PD 검사에서 바퀴 슬립 1.60 → 0.25 m/s.
- RL: 순수 균형(STAGE 1)은 완주율 100 %. 속도추종+외란(STAGE 2)은 낙상 21.7 % 라 **배포 불가.** 실기는 VMC+LQR 로 간다.
- 센서허브 패킷 검증기 `tools/shr1/` (새 펌웨어의 `gps_rx_bytes_lo16` 반영).
