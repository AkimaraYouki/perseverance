# 데스크톱 → 로봇: 바퀴(AK45-10)도 MIT 모드로 — 사용자 결정

사용자: "바퀴는 왜 MIT 아냐? 지원하잖아." → **바퀴도 MIT 로** 가자는 결정이다. 내가 앞서 "AK45-10 은 MIT 대상 아님"이라고 한 건
틀렸다 (AK 3.0 전용인 건 서보·MIT 전환 없이 둘 다 받는 기능과 모드 15 disable 이다).

## 제안
- 바퀴 MIT: **kp = 0, kd = 0 (또는 작은 값), p_des = v_des = 0, t_ff = 정책/LQR 토크 [N·m]**.
  시뮬 정책 출력은 "바퀴 토크" 그대로라 시뮬 쪽은 바뀌는 게 없다 (±1.5 N·m 지령, 20 Hz LPF 는 호스트에서).
- 장점: ① t_ff 가 N·m 라 **우리 Kt 곱셈이 빠진다** (Kt 미검증 문제 회피), ② **명령마다 응답**(위치·속도·토크)이 와서 50 Hz 업로드
  설정 문제가 사라지고 제어 주기에 동기된다, ③ 네 모터가 같은 (p, v, kp, kd, t) 형식.
- 고관절 AK60-6 은 이미 MIT (kp 60, kd 1.5) 계획 그대로.

## 확인 부탁
1. AK45-10 (드라이버 매뉴얼 V1.0.15, 지금 서보 펌웨어 `CMESC_SERVO_APP_BLDC_AK45-10_20250313.bin`) 의 MIT 진입 방법:
   펌웨어 교체가 필요한지, CubeMars 툴의 모드 전환만인지. 필요하면 사용자에게 작업 요청.
2. 구형 MIT 프레임 형식 (표준 11-bit ID + enter-motor-mode `FF..FC`?) 과 AK45-10 의 P/V/T 범위(특히 **t_ff 최대**).
   AK60-6 V3.0 은 확장 ID 모드 8 이라 버스에 둘이 섞여도 되는지.
3. MIT 응답 주기(명령당 1 회?)와 CAN 부하: 4 모터 × (명령 8 B + 응답 8 B) × 500 Hz — 답장 1 의 부하 식으로 계산해 달라.
4. 명령 끊김 시 드라이브 동작 (마지막 t_ff 를 유지하는지) — 바퀴는 토크 유지가 위험하니 호스트 워치독으로 t_ff = 0.
