# 데스크톱 → 로봇: CAD export (5) 반영 — 센서 프레임, 좌우 규약, COM, 게인 재검증

사용자가 CAD 를 다시 뽑았다 (onshape-to-robot v1, export (5)). 전부 반영해서
`sim/model/robot_simple.urdf`, `sim/control/gains.yaml` 을 갱신했다.

## 1. 좌표·이름 규약 확정 (ROS REP-103)

- CAD 자체가 이제 **+x 전진, +z 위**. 데스크톱에서 하던 90° 회전은 없앴다.
- **+y = 왼쪽.** `L_joint_*` / `l_*` 링크가 +y 쪽, `R_*` 가 -y 쪽. (export (3) 까지는 R 이 +y 에 있었다 — 사용자가 이름을 바꿨다.)
- 루트 링크 = `base_link`. 단순화 모델의 원점은 **두 고관절(다리 모터축) 중점**.
- 모터 CAN ID 를 `motors.yaml` 에 넣을 때 이 좌우 이름을 기준으로 해 달라.

## 2. 센서 프레임 (CAD 메이트 커넥터에서 뽑음, base_link = 고관절 중점 기준)

| 프레임 | xyz [mm] | rpy | 비고 |
|---|---|---|---|
| `imu_link` | (50.0, -5.0, 70.0) | 0 0 0 | 축이 몸체와 같다고 CAD 에 그려져 있다 → **iAHRS 실물 축 마킹과 맞는지 확인 필요** |
| `gps_link` | (50.3, -4.8, 86.4) | 0 0 0 | 센서허브 드라이버의 `gps_frame_id: gps_link` 와 이름 일치 |
| `laser` | (-77.4, 0.0, 122.5) | 0 0 π | 라이다를 뒤로 달아서 yaw 180°. 아래 3 절 확인 필요 |
| `camera_link` | (108.0, 0.0, 15.3) | 0 0 0 | +x 가 보는 방향. optical frame 은 여기서 파생 |

`sim/model/robot_simple.urdf` 에 fixed joint 로 들어 있다. robot_state_publisher 로 TF 를 낼 때 써도 된다
(다리는 prismatic 한 개로 단순화된 모델이라 다리 TF 는 실제 4절링크와 다르다).

## 3. 라이다 방향 확인 요청

RPLIDAR 몸체의 "앞" 표시와 드라이버가 내는 스캔 0°(+x)가 같은 방향인지 보장이 없다.
라이다 표시상 앞쪽에 물체를 두고 rviz 에서 Fixed Frame = `laser` 로 봐서
물체가 +x 에 보이면 yaw π 그대로, -x 에 보이면 yaw 0 으로 바꿔야 한다. 결과를 알려 달라.

## 4. COM 이 고관절선보다 7.9 mm 뒤 → 정적 기울기

CAD 영점 자세(h = 196.5 mm)에서 전체 COM 이 고관절-바퀴 선보다 **7.9 mm 뒤**다 (CAD 계산).
(+0.25 kg 추가 질량의 위치는 모른다 — 실측 필요.)
균형 상태에서 로봇은 COM 을 바퀴축 위로 가져오려고 **앞으로 약 2~4° 기울어** 선다
(h 가 낮을수록 크다). Isaac 에서 LQR 이 최대 3.3~4.8° 기울어 선 것과 맞다.

→ 실기에서 LQR 의 θ 기준을 0 으로 두면 이 기울기가 계속 오차로 잡혀
  **상시 토크나 x 방향 드리프트**가 생길 수 있다. 첫 기동 때 정지 상태의 θ 평균을 재서
  θ 오프셋(트림)으로 빼 주기를 권한다. 잰 값을 알려 주면 모델 COM 을 보정하겠다.

## 5. 관절 한계 재계산

CAD 를 다시 뽑으면서 관절 로컬 프레임이 바뀌어 이전 한계를 그대로 못 쓴다.
URDF 의 폐루프를 직접 풀어 다시 쟀다 (`sim/model/joint_limits_from_urdf.py`, 잔차 < 5e-7 m).
다리 높이 h 182.5~302.5 mm 에 해당하는 범위 (여유 0.05 rad 포함 전):

| 관절 | L (+y) | R (-y) |
|---|---|---|
| M (다리 모터) | -7.0° ~ 52.5° | -52.5° ~ 7.0° |
| I | -7.9° ~ 69.2° | -69.2° ~ 7.9° |
| K | -87.6° ~ 9.3° | -87.6° ~ 9.3° |

**CAD 영점 자세 = M 0° = h 196.5 mm = leg_map θ ≈ 45.0°.** 좌우 M 은 부호가 반대다.
다리 모터 영점을 CAD 영점 자세에 맞추면 `θ_leg_map = 45.0° + (±M)` 로 바로 변환된다
(부호는 모터 방향 확인 후).

## 6. VMC+LQR 재검증 (새 모델)

게인은 이전과 1 % 이내로 같다 (`sim/control/gains.yaml` 갱신).
Isaac 결과도 같은 패턴:

| h [mm] | 쉬운 조건 | 어려운 조건 (±8.6° 시작, 외란, 질량/COM 랜덤) |
|---|---|---|
| 182.5 | 16/16 | **16/16** |
| 212.5 | 16/16 | **16/16** |
| 242.5 | 16/16 | 9/16 |
| 272.5 | 16/16 | 3/16 |
| 302.5 | 16/16 | 3/16 |

첫 기동은 여전히 **h ≈ 190~210 mm** 권장.

## 7. 기타

- CAD 에 라이다·배터리·GNSS 파트를 넣었지만 **질량이 안 들어가 있다** (총질량 4030.3 g 로 이전과 같음). 계속 "모델 + 0.25 kg" 을 쓴다.
- 데스크톱 RL 체크포인트는 옛 모델 것이라 무효다. 실기는 VMC+LQR 로 간다.
