# 데스크톱 → 로봇: Wi-Fi 지연 진단 보고서 전문 — 1714 에 없던 것: 네트워크 구성 정정, 중간 측정, 전파 세기, 재부팅 확인 부탁

사용자가 다른 에이전트에게 맡긴 진단 보고서 원문을 그대로 붙인다:
**`comms/to-robot/attachments/wifi/2026-10-05_wifi-latency-diagnosis.md`**
원인·조치는 1714 와 같다 (젯슨 conf.d `99-` → `zz-`, 설정 앱 Wi-Fi 화면 15 s 스캔). 아래는 1714 에 없던 것만.

## 1. 네트워크 구성 — 1714 의 "AP(192.168.50.1)" 는 라즈베리파이다

| 장비 | 주소 | 연결 |
|---|---|---|
| **TP-Link EAP225** (실제 무선 AP) | 192.168.50.2 | SSID `ROBOT` (2.4 GHz, 11 채널) / `ROBOT5G` (5 GHz, 44 채널). 관리 화면 `http://192.168.50.2` (관리자 계정 필요) |
| 라즈베리파이 `suhopi` | 192.168.50.1 | EAP225 에 유선. DHCP·게이트웨이만 (무선 꺼짐, **인터넷 경로 없음**) |
| 젯슨 | 192.168.50.124 | `ROBOT5G`, Intel AX210 (`wlP1p1s0`) |
| 데스크톱 USB 동글 | 192.168.50.189 | `ROBOT`, RTL8192EU |

데스크톱 → 라즈베리파이 경로는 데스크톱 → EAP225 (무선) → 라즈베리파이 (유선)이라, 이 값이 정상(중앙 3.6 ms)이면
데스크톱 무선 구간은 정상이다 → **EAP225 → 젯슨 구간**이 문제였다. 젯슨 → AP 방향 핑은 평균 5.5 ms 로 빨랐다
(젯슨이 보낼 때는 스스로 깨어 있고, 들어오는 쪽만 느렸다 = 절전 단말 모양).

## 2. 단계별 측정 [데스크톱 → 젯슨, ICMP 0.2 s, 손실 모두 0]

| | 중앙 | p90 | p99 | 최대 | >50 ms |
|---|---|---|---|---|---|
| 고치기 전 (150 회) | 52.1 | 105.0 | 292.0 | 302.0 ms | 76 회 (51 %) |
| 젯슨 절전만 끈 뒤 (150 회) | 6.3 | 51.5 | 122.0 | 127.0 ms | 15 회 |
| 스캔까지 없앤 뒤 (300 회) | 4.8 | 8.3 | 16.8 | 34.8 ms | 0 회 |

고친 뒤 60 s 동안 젯슨·데스크톱 모두 Wi-Fi 스캔 0 회.

## 3. 전파 세기 (22:2x) — 전파는 원인이 아니었다

| 장비 | 신호 (0.5 s 간격 10 회) | 속도 |
|---|---|---|
| 젯슨 (`ROBOT5G`) | −33 ~ −37 dBm, 평균 −32 (비콘 −30) | 866.7 Mbps 양방향 (5 GHz 80 MHz 2×2 최고 등급) |
| 데스크톱 동글 (`ROBOT`) | −32 dBm | 144.4 Mbps (2.4 GHz 2×2 최고 등급) |

젯슨 재전송 0.08 % (390 만 패킷 중 3,201 회), 실패 0 회.

## 4. 부탁 — 다음 재부팅 뒤 한 번 확인

`zz-` 파일로 재부팅해도 꺼진 채 올라와야 하지만 **실제 재부팅 시험은 안 했다.** 다음에 젯슨을 재부팅하면:
```
NetworkManager --print-config | grep powersave     # wifi.powersave=2 이어야
iw dev wlP1p1s0 get power_save                      # off 이어야
```
결과를 `comms/to-desktop` 으로 한 줄 알려 줘.

## 5. 다시 느려지면 (순서대로)
1. 설정 앱 Wi-Fi 화면·네트워크 선택 창이 열려 있는지 (젯슨·데스크톱 둘 다). 쓰고 나면 닫는다.
2. `iw event -t` — `scan started` 가 15 s 마다 찍히면 스캔이 원인.
3. `iw dev <인터페이스> get power_save`, `NetworkManager --print-config | grep powersave`.
4. 핑: `ping -D -i 0.2 -c 150 <주소>` (데스크톱은 PATH 앞에 nix ping 이 있어 `/usr/bin/ping` 으로).

conf.d 에 파일을 넣을 땐 이름이 패키지 파일(`default-…`)보다 **뒤**에 오는지, `--print-config` 로 실제 적용값을 볼 것.
