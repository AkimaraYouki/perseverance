# 데스크톱 → 로봇: 8–10 Hz 는 "주 루프 지연 15–20 ms" 로 재현된다. 엔코더 지연 (백래시) 만으로는 안 된다 → 낮은 이득 표로 지연 가설부터 가르자

## 1. 재현 [측정, 시뮬, 평지 서 있기 6 s, 모델 오차 끔]
| 조건 | θ̇ σ | 바퀴 토크 σ | 주파수 |
|---|---|---|---|
| 제어 지연 5 ms (지금까지 시뮬) | 0.07 rad/s | 0.22 N·m | – |
| 제어 지연 10 ms | 0.10 | 0.24 | – |
| 제어 지연 15 ms | 1.23 | 1.16 | 10 Hz |
| **제어 지연 20 ms** | **1.66** | **1.43** | **8 Hz** |
| 통신 9 ms + **바퀴 엔코더만** 15 ms 늦게 (너희 톡 치기) | 0.26 | 0.39 | 10 Hz (작음) |
| 위 + IMU 가속 융합 속도 추정 (1 / 2 / 4 Hz) | 0.24 / 0.55 / 0.44 | | 효과 없음 |
| **실기 (균형 2·3)** | **1.74** | ≈ 2 | **8.4–9.6 Hz** |

→ 실기 크기는 **자이로 → 바퀴 토크 주 루프가 15–20 ms 늦을 때만** 나온다. 엔코더 (속도 추정) 쪽 지연은 같은 주파수의 작은 흔들림만 만든다.
측정된 9 ms 말고 어딘가 더 늦다. 의심 순서 [추정]:
1. **고관절 kp 가 200 Hz 호스트 t_ff** — 로그에서 다리도 같은 주파수로 ±3 mm 튄다. 시뮬은 고관절 PD 가 이상적이다.
   가능하면 kp 도 드라이브로 (MIT p_des: 60° 판별 끝난 뒤의 드라이브 위치로 M* 를 바꿔 넣기).
2. 바퀴: 전류 응답 3–5 ms 는 쟀지만 **토크가 땅에 닿는 시간** (백래시를 건너는 시간) 은 안 쟀다.
3. 제어 스텝 안의 순서 (IMU 읽기 → 계산 → CAN 송신) 와 바퀴 20 Hz LPF 를 합친 실제 위상 지연.

## 2. 시험 부탁 — `sim/model/balance_tables_lowgain.yaml`
`lqr_l / lqr_k` 만 이걸로 바꿔 같은 균형 3 (롤 끔, 손 가볍게) 을 해 줘. Q θ̇ 5 → 1, R 1 → 2 (K(0.25) = [−1.0, −2.32, −12.98, −1.70], 지금 [−1.41, −3.36, −18.61, −3.34]).
시뮬: 지연 20 ms 에서 서 있기 θ̇ σ 1.66 → 0.20 (조용).
- **조용해지면** 지연이 원인 확정 → 1 의 지연을 줄이는 쪽으로 간다.
- 그대로면 지연이 아니라 모델 (관성·Kt·백래시) 문제다.
주의: 이 이득은 서 있기 확인 전용. 지연 20 ms 의 시뮬 전체 시나리오 (11 종 × 16 대) 는 기본 이득 45/176, 낮춘 이득도 비슷하게 무너진다 — 주행은 지연을 줄여야 한다.

## 3. 롤 루프
같은 지연에서 맞춘 값은 아직 없다. 시뮬 (지연 5 ms) 에서 roll_kd 0 은 다른 시나리오는 그대로지만 **손으로 들어 기울여 놓기가 무너진다** (10°: 15 → 5/16, 20°: 12 → 2/16).
→ 피치 진동을 먼저 잡을 때까지 롤 끈 채로 시험하자. 피치가 잡히면 같은 지연으로 roll_kd 0.1·rate LPF 낮춤을 시뮬에서 맞춰 보내겠다.

## 4. 그 밖 (시뮬 쪽 고친 것)
- `enc_delay_ms` (시뮬 전용 엔코더 지연), `v_fuse_hz` (IMU 가속 융합 속도 추정, 바퀴축 = 몸통 속도 − h·피치 각속도) 를 wbctrl 에 넣었다. 둘 다 기본 끔.
- 바퀴 마찰 무작위화에서 운동 > 정지 가 되는 로봇이 있어 PhysX 가 설정을 거부하던 것 고침.
- 무게중심 오차 ±2 cm 를 제어기가 모르게 하니 (명목 표) 시뮬 성공률이 169 → 127/176 으로 떨어졌다 (버그 아님, 오차 0 이면 169). 실기에선 첫 정지 때 `th_bias` 가 이걸 잡아야 한다 — 기록해 줘.
